上一篇把大界面认清了：主页挑项目、三栏里干活、输入框那圈开关调方式。

还剩最深一层没讲，就是设置中心。这一层配一次，长期受益，它决定这台工作台是能用还是顺手。

01

PART


先找到门

ENTRY · 设置在哪儿

它不在顶部菜单，也不在右上角。在左下角那个齿轮。

— 左下角齿轮点开，Settings 就在弹窗里

点一下齿轮，弹出一个小窗，里面是你的账号、套餐，以及 Settings。点进去，就是这一篇要讲的十一个面板。

很多人卡在这一步，把界面翻了个遍也没找到设置在哪。记住位置就行：左下角，齿轮。

02

PART


进门先认路

MAP · 左边就两组

进去第一眼是十一个子页，看着挺唬人。别慌，软件自己已经分好组了。

— 左栏两组：上面能力配置，下面工作区设置

上面 Capabilities（能力配置）六个：Skills、Connectors、Specialists、Memory、Compute、Network。决定的是它能调用哪些能力：多一门技能、多一个数据库、多一块算力。

下面 Workspace（工作区设置）五个：Permissions、Credentials、Storage、Usage、General。管的是工作区本身：权限给到哪、凭据存哪、数据放哪、用量花在哪。

记住这两句，后面就不会乱

上面配它的能力，下面配你的工作区

03

PART


先照这四条设

QUICKSTART · 开箱清单

不想读完？十一个面板，真正开箱就得动的只有四条。改完就能用，剩下的用到再回来查。

1

General → Licensing 改成 Non-commercial。做科研的必改。默认是 Commercial，很多开源组件对商用有授权限制，不改会时不时弹出授权确认拦你一下。改成学术用途就顺了，这条几乎没人提。

2

General → Contact email 填上。它替你去 NCBI、EBI 这类学术站点抓数据时，会带上这个邮箱做身份标识。这是那些站点的规矩，不填容易被限流。

3

Memory → 打开。默认是关的。打开之后，论文主题、目标期刊、写作偏好这些不用每次重讲。记忆存在你本机，不传给 Anthropic。

4

Storage → 换到非 C 盘。还记得 Day 3 那次 C 盘跑爆吗？根子就在这。光一个 Conda 环境就 8.3 GB，早点挪走，省一次事故。

下面十一个面板挨个过一遍，每个就几句话，看完心里有数就行。

04

PART


能力配置

CAPABILITIES · 六个面板

TOOL 01

Skills：给 AI 装特长

技能就是插件。Featured 是官方精选，Imported 从 GitHub 导，Personal 是你自己写的。

— Skills：十六个官方技能

这里有句实话得说在前面。官方那十六个技能，清一色是生物方向：AlphaFold2、Boltz、ESM-2、DiffDock、ProteinMPNN、scGPT 这些。做蛋白、分子、单细胞的，开箱即用，很爽。

！先说清楚 🕳

不是生物方向的，Featured 这一栏基本指望不上，里面只有 Literature Review 算通用。能力得靠自己从 GitHub 导，或者自己写。先知道，省得装完发现用不上。

TOOL 02

Connectors：直连学术数据库

连接器是它伸出去查库的手。bioRxiv、ChEMBL、Clinical Trials、PubMed 这些开关一开，它就能自己去查，不用你复制粘贴。

— 目录，以及那条连不上 claude.ai 的报错

顺便说个真坑。截图里那条红色报错是我自己截的，不是演示。这个目录要联 claude.ai 才拉得出来，国内网络下经常拉不出来，界面上就是空的。

！踩坑提示 🕳

这不是软件坏了，是网络没通，通了它自己就回来。看到这个别急着重装。

TOOL 03

Specialists：换个专业身份

一套技能加连接器加指令打包成的角色。目前只有一个内置的：Reviewer（审稿人）。开了它，AI 就用审稿人的苛刻视角看你的稿子。平时保持默认，投稿前切过去让它挑一遍毛病。

— 内置的 Reviewer 角色

TOOL 04

Memory：记住你的背景

右上角那个总开关默认是 Off，记得手动开。左边可以自己建分类。

— 总开关默认是关着的

再强调一次：这些记忆存在你本机的本地库里，你随时能看、能改、能删。

TOOL 05

Compute：代码在哪跑

三块：SSH hosts 接你自己的服务器，Cloud providers 接云端 GPU，Model endpoints 接专业科学模型。

— SSH / 云 GPU / 模型端点

默认 Local，也就是在你自己电脑上跑。未发表的数据，保持 Local 最稳，要大算力时再来接。

TOOL 06

Network：镜像和白名单

上半填 Conda 和 pip 的国内源，装包慢的时候来这配。下半是科研域名白名单，按类别开关，用哪类开哪类。

— 包镜像 + 科研域名白名单

这一节跟上面 Connectors 那个坑是一回事：网络通不通，很大程度决定它能不能干活。

05

PART


工作区设置

WORKSPACE · 五个面板

TOOL 07

Permissions：它能动你哪些东西

上半 Registry writes 是系统级的八项，作用域是全局。下半 Local compute 是它调 Python 和 Bash 的权限。

— 系统写入 + 本地计算权限

有个细节值得留意：bash 的调用权限是绑到具体项目上的，不是一给就全局通行。觉得给多了，右边 Revoke all 一键收回。

TOOL 08

Credentials：外部服务的钥匙

AWS、GitHub、Google Cloud、期刊访问、Azure、Modal、NVIDIA API、OpenAlex，八个服务的凭据统一存这。

— 八个外部服务的凭据

用到哪个填哪个，一开始一个都不用填。

TOOL 09

Storage：换盘在这操作

Data location 就是改盘的地方。注意有活跃会话时改不了，得先把会话关掉。

— 数据路径 + 磁盘构成

底下那个构成拆得很细，看一眼就知道为什么必须挪盘：Artifacts 才 16.1 MB，Conda 环境直接 8.3 GB，占了大头。跑几个项目下来，C 盘扛不住。

TOOL 10

Usage：钱花哪儿了

那个环形图是这个面板最值钱的东西。它把 token 花在哪拆得明明白白：Assistant prose 18%、Tool calls 33%、Artifact provenance 1.8%，Reviewer 47%。

— token 去向：审查员占了近一半

审查员一个人吃掉了将近一半

它确实好用，但它是这里最贵的开关

TOOL 11

General：前面那两条改在这

这一页管账号、模型、授权、外观。第三节说的 Licensing 和联系邮箱，都在这改。

— 模型设置 + Licensing 两个选项

Model 那块有四个下拉，前三个好理解。第四个值得单独说：Reviewer model 可以单独设。

这就跟上一节接上了。审查员吃掉 47% 的 token，而它用哪个模型你能自己定。想省钱，就把审查员调成便宜的小模型；要严格把关，再调回大的。

贵在哪、能不能调、在哪调，这三件事到这儿就串成一条线了。
