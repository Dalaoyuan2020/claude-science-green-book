PART


周三凌晨，我的 C 盘满了

STORY · 磁盘体检上首页

我自己就是 CSA 的头号用户。周三凌晨实验跑到一半，Windows 弹出磁盘空间不足，整台电脑卡成幻灯片。

查明白才知道：CSA 的底层环境住在一个虚拟磁盘文件里，它只会越长越大，默认还赖在 C 盘。你跑实验、下数据集，它就在看不见的地方一口一口把 C 盘吃光。我把它搬去 E 盘才救回来，折腾了半宿。

我懂点原理都这么狼狈，刚装好 CSA 的科研人大概率只能对着卡死的电脑干瞪眼。所以 v0.1.3 把「磁盘体检」直接做上了首页：

— v0.1.3 新界面：六项状态＋WSL 存储体检，真机截图

新界面那格「WSL 存储」盯着三个数：虚拟磁盘住哪个盘、那个盘还剩多少、里面的系统还剩多少。任何一头掉到 15G 以下，提前亮警告；发现它赖在 C 盘，提示你搬家。首页也重排了：六项状态两行摆齐，哪里不对一眼看到。

02

PART


后台喊得最响的：DeepSeek 连不上

FEEDBACK · 一桩方言冤案

Day 2 发出去，反馈里喊得最响的是这句：DeepSeek 接不上，MiniMax 也不行，Key 明明是对的。

挖下去发现冤情了：Key 真没问题，问题在「方言」。Claude 说话带自家的「思考」参数，DeepSeek 和 MiniMax 的接口听不懂，整句打回，CSA 就误以为你的 Key 坏了。

v0.1.3 给这两家各配了个贴身翻译，先翻成对方听得懂的再送出去。修完拿真实请求从头到尾验过：DeepSeek 流式、非流式全部通过，MiniMax 也接通对话。现在 Key 填进去，添加、测试、映射、开跑，一条道走到黑。

顺带说明：DeepSeek 走的是官方原生兼容地址，MiniMax 走的是中国区官方地址，都是官方直连，不绕弯。另外这次还修了一处误判：连通测试不再用极小的输出额度去试探，有效模型不会再被误判成失败。

03

PART


它怎么变「懒」了？

HIDDEN · 说话额度撤限

第三个问题最隐蔽。最早用官方订阅版时，这搭档非常主动：查文献，它自己把检索、存档、统计、画图一路干到底。可切到 API 接入之后，它就变得畏畏缩缩：干两步就停，回答短得敷衍，图也懒得画了。同一个模型，两副面孔。

这个对比把根因暴露了：模型没变笨，是 CSA 坑了它。订阅版的请求不经过 CSA 转发，所以生龙活虎；老版本转发时，私自给模型限死了一个不大的「说话额度」，模型一开口就快到上限，自然长话短说、能省则省，看起来就懒了。

v0.1.3 把这个设限撤了：能说多长说多长，该调用工具就放手调用。装回去再跑同样的活，那个一路干到底的搭档回来了：

— 修好后的真实会话：一句话跑完 20 篇检索、四联图、报告＋文献矩阵

这一单它自己跑完 PubMed 检索 20 篇、结构化分析、画出四联分布图，交出综述报告＋文献矩阵两个成品文件，交稿前还把作者名、引用错误自己审计修正了。这才是你该拿到的搭档。

04

PART


升级：一句话丢给 AI

UPGRADE · 三步＋照抄 Prompt

这次升级立了三条规矩：不卸载、不重装、Key 不丢。老版本不用删，你只做三件事：

1

GitHub 仓库 Releases 页，下载 v0.1.3 的完整压缩包（别只下 exe，更新的不止它一个）

2

解压到一个新文件夹，别覆盖旧的

3

交给你的 AI 编程助手（Codex、Claude Code 都行），发它下面这段

. . . PROMPT

请协助我在这台 Windows 电脑上安装或升级 CSA。当前文件夹是我刚解压的新版完整包。

　

要求：

1. 先读 README.md 和 docs/prompts/ 里的安装升级说明

2. 只做只读体检，判断我是首次安装还是老版升级，把计划讲给我听，我确认后再动手

3. 升级时不卸载 WSL，不清空设置，不动我已保存的 API Key

4. 旧版文件夹先留着，万一不顺利可以退回去

5. 装完做一次连通测试和一次真实对话，确认没问题才算完

还是那个思路：先立规矩，再干活。AI 体检、报计划、你点头才动手，旧版留着兜底。首次安装同一段话，AI 自己分流。
